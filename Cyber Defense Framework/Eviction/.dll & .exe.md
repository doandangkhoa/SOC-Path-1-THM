Sự khác biệt cơ bản nhất giữa file **DLL** (`.dll`) và file **EXE** (`.exe`) nằm ở **cách chúng thực thi** và **mục đích sử dụng** trong hệ điều hành Windows.

Dưới đây là bảng so sánh chi tiết:

| Đặc điểm | File EXE (Executable) | File DLL (Dynamic Link Library) |
| --- | --- | --- |
| **Khởi chạy** | Có thể chạy độc lập. Bạn chỉ cần click đúp vào file để mở chương trình. | **Không thể chạy độc lập**. Bắt buộc phải có một file EXE (hoặc công cụ như `rundll32`) gọi nó mới chạy được. |
| **Mục đích** | Là một chương trình hoàn chỉnh (ứng dụng, game, công cụ). | Là một "thư viện" chứa các hàm/chức năng dùng chung cho nhiều chương trình khác nhau. |
| **Truy cập bộ nhớ** | Chạy trong một không gian bộ nhớ riêng biệt. | Có thể được nhiều chương trình cùng sử dụng (chia sẻ bộ nhớ), giúp tiết kiệm RAM. |
| **Entry Point** | Có điểm vào chính (`main()` hoặc `WinMain`) để khởi động. | Không có điểm vào chính, chỉ có các hàm được định nghĩa để người khác gọi. |
| **Biến đổi thành virus** | Dễ dàng tạo file virus EXE tự chạy. | Chỉ trở thành mối đe dọa khi bị một quy trình hợp lệ (như `rundll32`) gọi để thực thi mã độc bên trong. |

### Giải thích chi tiết:

#### 1\. File EXE (.exe) - "Người lái xe"

- **Đặc tính:** Đây là một ứng dụng độc lập. Nó có mã nguồn khởi động (Entry Point) của riêng mình.
- **Cách hoạt động:** Khi bạn nhấp đúp, Windows load file này vào bộ nhớ và bắt đầu thực thi từ dòng lệnh đầu tiên.
- **Ví dụ:** `chrome.exe`, `notepad.exe`, `game.exe`.
- **Trong bảo mật:** Nếu file EXE chứa virus, nó sẽ tự động chạy ngay khi người dùng mở nó. Đây là dấu hiệu dễ bị phát hiện nhất.

#### 2\. File DLL (.dll) - "Hộp công cụ dùng chung"

- **Đặc tính:** Nó giống như một kho chứa các công cụ (hàm mã lệnh) mà các chương trình khác có thể mượn để sử dụng. Nó không có "đầu" để tự bắt đầu chạy.
- **Cách hoạt động:** Nó cần một "người gọi" (caller). Ví dụ: Khi bạn mở trình duyệt Chrome, nó sẽ gọi các file DLL để xử lý âm thanh, hình ảnh, mạng... mà không cần viết lại các mã đó trong chính file Chrome.
- **Ví dụ:** `kernel32.dll` (hệ thống lõi), `user32.dll` (giao diện), `msvcrt.dll` (C++ runtime).
- **Trong bảo mật (Kỹ thuật DLL Injection/Proxy Execution):**
    - Vì DLL không tự chạy, nên nếu một file DLL độc hại bị đặt vào thư mục hệ thống, nó sẽ **không tự động kích hoạt** và gây hại ngay lập tức.
    - Nó chỉ nguy hiểm khi kẻ tấn công dùng một lệnh (như `rundll32.exe`) để "ép" Windows tải file DLL đó lên và chạy hàm mã độc bên trong.
    - **Tại sao kẻ tấn công thích dùng DLL?** Vì file DLL trông giống hệt các file hệ thống hợp lệ. Nếu bạn nhìn thấy `malicious.dll` đang chạy thông qua `rundll32.exe`, hệ thống bảo mật có thể lầm tưởng đó là một quy trình hợp lệ đang làm việc, trong khi thực tế là mã độc đang hoạt động.
